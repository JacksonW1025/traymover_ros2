# 选项 10：NDT 自动纠偏

`./scripts/traymover.sh` 的选项 10 自动启用 `auto_correction_enabled:=true`，无需新增输入。每次运行的 `logs/nav/<本次运行>/run_info.txt` 记录该设置。高度加权仍使用原有独立输入。

两级 launch 和节点默认关闭自动纠偏，因此其他导航入口保持原行为。直接调用 `traymover_nav.launch.py` 时，可显式传入 `auto_correction_enabled:=true` 做回放或对照；省略该参数或传入 `false` 使用原门限逻辑。

## 纠偏方式

较高的 `score_threshold` 允许更多候选通过分数检查，但不能证明候选位置正确。自动纠偏保留收敛、有限值和分数检查，沿用用户当前配置的 `score_threshold`。对于较小修正自动应用，对于超过原跟踪门限的修正，要求候选在限定范围内、相对预测位姿的匹配分数改善，并通过连续多帧一致性确认。单帧大跳变不会直接更新定位。

确认后的修正分步应用。平移限制按最新 odom 下机器人当前位置的实际修正量计算，避免远离 odom 原点后，小角度修正被误判为巨大的平移跳变。内部预测使用已接受的原始匹配结果，发布给导航的变换单独平滑，防止输出平滑造成的滞后继续污染下一帧的匹配初值。

预测使用点云时间戳对应的 odom TF。`/pcl_pose` 和路径使用已经施加的平滑修正，与该扫描时刻的 TF 一致；`ndt_aligned_scan` 保留优化器的原始对齐结果用于对照。高度加权开启时，候选及预测的质量比较均使用不含高度副本、但保留原有远点权重的同一份点云。

默认策略：

| 条件 | 行为 |
| --- | --- |
| 超过原跟踪门限 0.35m 或 0.45rad | 进入多帧确认，不再单凭该门限永久拒绝 |
| 超过绝对上限 2.5m 或三维旋转角 0.60rad | 拒绝，不通过平滑掩盖超大跳变 |
| 大修正的匹配质量 | 比该帧预测位姿的分数至少改善 1% |
| 大修正连续性 | 连续 3 帧候选相对同一锚点的一致性为 0.20m / 0.10rad；帧间隔最多 6s |
| 输出平滑 | 沿用平滑系数 0.30，每次应用最多 0.15m / 0.08rad |

一致性比较的是运动补偿后的校正变换，机器人正常前进不会要求三帧停留在同一地图位置。实际参数可在定位配置中查看；修改前应保留一组关闭功能的对照数据。

启用自动纠偏时，odom 增量另有粗粒度异常筛查：平移速度 2m/s、垂直速度 0.5m/s、角速度 1.5rad/s，并有固定测量抖动余量。触发后锁定异常状态，停止发布新的 `map→odom`，直到重新初始化。这些是明显异常的筛查线，不构成完整的 FAST_LIO 健康判断或恢复机制；重新初始化前应确认里程计已经恢复可信。

单纯的观测或处理时间间隔过长只会清空确认、丢弃本次候选，不锁存里程计故障。缺失 TF、评分失败、未收敛以及重复或倒序扫描也不能用于凑足确认帧数。初始化仍使用独立的初始化范围；这里的分帧纠偏用于已经建立定位后的跟踪阶段。

日志中的 `NDT auto correction: evidence=` 记录确认进度和评分比较，`applied translation=` 记录实际修正及剩余偏差，其他同前缀警告说明本次拒绝原因。配置中的 `auto_correction_*` 参数可调整策略；启用时要求正有限范围、至少两帧确认、有效平滑系数，并使用扫描驱动的位姿发布。

自动纠偏只使用当前局部 NDT 候选，不是全图重定位。错误初值若落入重复结构的另一个局部最优，或者 FAST_LIO 已严重发散，仍可能无法恢复；过大的候选继续拒绝。未通过校正的帧不会因为启用此功能就被当作成功定位。

## 验证方式

TF 重发使用独立回调组与两线程 executor。定位、初始位姿和里程计回调仍在同一个互斥组中，
TF 线程只读取受互斥锁保护的已验收变换快照，不读取或修改优化器状态。重新初始化、
里程计故障及节点停用会使快照失效；即使有排队点云，停用期间也不会重新发布定位 TF。

`scan_odom_tf_timeout` 默认 0.5 秒，等待准确扫描时刻的里程计 TF，不以最新 TF 冒充。
缺失 TF 的尝试不会消耗 `ndt_align_interval_s`，下一份有效扫描可以及时重试。
运行中重新设置初始位姿仍会暂时停止定位 TF，可能中止已有导航目标；这与正常匹配期间
独立持续重发 TF 是两种不同状态。

选项 10 的 `ndt_events.log` 每个报告周期增加 `event=MOTION`，汇总 `/cmd_vel` 的最新六维值、
累计/周期接收次数、非零次数及消息年龄，以及总急停、自动急停、手动急停和电机使能状态。
未收到状态显示 `unknown`，不把它当作已解除急停。该采集是被动订阅，不发布速度或改变急停。
`motor_status_speed_x/th` 是 PWM，未将其当作测量速度记录。

对同一段点云和里程计分别启用、关闭自动纠偏，比较连续拒绝时长、接受修正量、轨迹与静态结构重合程度以及计算耗时。应包含初值偏差、走廊远离 odom 原点、单帧错误匹配及连续一致候选四类情况。fitness 降低本身不足以证明位置更准确，机场重复结构场景仍需实车或已知轨迹对照。

## 初始化停在 TF 查询时

若日志持续出现 `scan-time odom unavailable` 和 `two or more unconnected trees`，
NDT 尚未开始匹配，提高 Fitness 门限不能解决。选项 10 要求
`odom → camera_init → body → base_link`；旧选项 20 遗留的
`base_footprint → base_link` 会争用同一个子坐标系，导致初始化无法建立定位。

选项 0 现在包含项目已知静态 TF 发布进程的清理。选项 10 在生成运行地图及启动硬件前，
通过 `scripts/cleanup_static_tf.py` 检查当前用户、当前 ROS 域中的已知静态发布者：
仅清理启动器已退出、被 systemd/init 接管的遗留进程；发现上一导航仍在运行时中止新启动。
不会把断开的 TF 当作零位姿，也不绕过扫描时刻的 TF 校验。
