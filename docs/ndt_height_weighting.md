# NDT 高处结构加权实验

选项 10 在启动硬件前询问本次 NDT 高度门限。输入非负十进制数（例如 `2.0`）启用，直接回车关闭；输入无效会重新询问，输入结束会取消启动。每次启动独立选择，不修改 YAML。默认关闭。

门限是 **`base_link` 坐标系的 z，单位米**，不是离地高度，也不是地图高度。点云先变换到机器人基座坐标系；这里不会利用可能漂移的地图高度。车体倾斜时基座 z 也随之倾斜，本补丁不做地面或重力方向补偿。

## 匹配行为

体素降采样和距离过滤后，`z >= height_boost_min_z` 的实时源点增加一份副本，使其在 NDT 目标函数、梯度和 Hessian 中贡献更多。低处点保留，地图不变。沿用现有远点加权，高度副本最多把总份数增至 3；若原有远点倍数已经大于等于 3，保留原倍数，不再添加高度副本。

默认远点倍数为 2 时：

| 点类型 | 源点份数 |
| --- | --- |
| 低处近点 | 1 |
| 低处远点 | 2 |
| 高处近点 | 2 |
| 高处远点 | 3 |

验收仍按原有源点分布计算 fitness：保留原有远点副本，不包含新增高度副本。`score_threshold` 不变。另行记录加权 fitness 作为诊断，不能把加权分数降低直接当作定位改善。日志提供点数和匹配/评分耗时；启用后的额外评分也有计算成本。

评分现按每个唯一源点查询一次最近邻，再按原有远点份数及新增高度份数分别累计两种均值。
这与重复点云的评分口径等价，同时避免两次遍历重复点做最近邻搜索；不会在评分时切换
registration 的输入点云。日志中的 `nn_queries` 是本次实际查询点数。

`logs/nav/<本次运行>/run_info.txt` 保存 `height_boost_enabled`、`height_boost_min_z`、`height_boost_frame=base_link` 和固定 `height_boost_extra_copies=1`。后者是请求的高度额外份数，实际是否添加仍受总份数上限约束。

两层 launch 参数也支持回放或明确的命令行实验：

```bash
ros2 launch traymover_robot_nav traymover_nav.launch.py \
  height_boost_enabled:=true height_boost_min_z:=2.0
```

## 对照验证

用同一路段、同一段点云/IMU 数据分别关闭和开启加权，比较成功校正次数、连续拒绝时长、轨迹跳变、原口径 fitness、匹配/评分耗时。检查超过门限的实际点数；如果几乎没有高处回波，升高门限不会带来帮助。

高处天花板或重复梁虽然稳定，可能不能约束走廊方向的位置。这个实验不剔除行人、不修复 FAST_LIO 发散，也不改变扫描与里程计的时间对齐逻辑。现场效果需要回放和实际路段对照，自动化测试只证明加权、参数传递和输入处理符合设计。
