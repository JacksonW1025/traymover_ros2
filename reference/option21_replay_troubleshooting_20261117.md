# 选项 21 仿真回放显示检查（2026-11-17）

在仓库根目录执行：

```bash
./scripts/replay_option21_simulation.sh logs/option21_airport/nominal_rate changed_s101_wheel
```

`wheel` 最后有字母 `l`；`changed_s101_whee` 会被参数检查拒绝。
绿色是真值，橙色是原始里程计，蓝色是 NDT 修正后的轨迹；机场视角采用接近俯视的全场视角。

## 已修正的回放问题

- 旧 bag 的 `/simulation/map` 头部时间戳是系统时间（约 1794903207 秒），而轨迹、TF 使用 10～147 秒仿真时间。新实验统一使用仿真时间；回放辅助节点将旧 bag 的静态地图时间戳设为 0，仅在内存中处理，不修改原始 bag。
- 地图和静态 TF 原先只在 bag 开头发布一次。辅助节点以可靠、持久 QoS 周期补发，支持迟到订阅以及循环回放。
- 等待 RViz 地图、点云、轨迹订阅就绪后才开始播放。关闭 RViz 或任何回放进程异常退出会清理本次脚本的其他进程。
- 补全显示总开关、固定相机参考系、窗口布局，机场配置增加 Views 面板和俯视角。总开关在 RViz 内部默认开启，缺失此字段不能单独认定为黑屏原因。
- 每次运行保留 `logs/option21_replay/<时间_进程号>/rviz.log`；启动失败或非正常退出会在终端打印日志末尾。

## 实际验证与边界

使用实际 ROS 2 Humble RViz 库构造测试窗口、加载配置，连接实际回放 bag，读取各显示插件的内部状态：地图 157139 点、实时 LiDAR 约 11000 点、四条轨迹均收到数据，地图/点云变换以及完整 TF 链状态正常。测试进程自动结束后，播放器和静态发布进程均随之退出。

另有 4 项回放回归测试，覆盖旧 bag 地图时间戳修复、源数据库不变、缺失静态 TF 的错误提示、两套 RViz 配置。选项 21 的相关测试合计 19 项通过。

当前桌面工具未提供本机窗口访问，未直接观察用户屏幕。上述验证证明数据和显示插件状态正常，不能单独证明用户窗口的最终 GPU 渲染画面。原配置在内部状态检查中也能收到数据，因此尚不能将用户报告的整个三维区域黑屏、自动退出明确归因于某一项配置。

如果重新运行后仍黑屏，展开 `Synthetic Airport Hall → Status` 查看消息数量、Points 和 Transform；若自动退出，查看终端打印的 RViz 日志路径。启动最初几秒尚未出现 `map→odom` 时，机器人 TF/动态点云可能短暂等待，静态地图应可独立显示。
